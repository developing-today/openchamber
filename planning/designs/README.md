# Designs

A design record says what a feature will be and why it takes that shape. Write one when the shape has to be decided before code, and when the decision involves a product call. Use the [design record template](../templates/design.md).

Name a record `<UTC datetime>_<kind>_<name>.md`, for example `2026-10-18T14-30-00Z_design_session_rows.md`. Link it from the roadmap row it belongs to. Append later changes as dated sections and leave the earlier text alone.

A record that involves a product decision stays `draft` until the maintainer decides in the session. See the rules in [`planning/README.md`](../README.md).
