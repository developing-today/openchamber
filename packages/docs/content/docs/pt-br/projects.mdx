# Projetos

Um projeto é uma pasta no seu computador que o OpenChamber acompanha — geralmente uma base de código. Trocar de projeto troca a pasta em que o agente trabalha, junto com as sessões e configurações daquele projeto.

## Adicionar um projeto

Você pode adicionar um projeto a partir de alguns lugares:

- a entrada **Add project** na paleta de comandos
- o botão **+** no topo da barra lateral de sessões
- o navegador de pastas quando você escolhe um diretório

Aponte-o para uma pasta e o OpenChamber a memoriza. O nome vem da pasta; você pode mudá-lo depois.

## Trocar de projeto

Escolha um projeto na barra lateral para torná-lo ativo. Tudo — sessões, git, notas — segue o projeto que você tem aberto.

## Tornar um projeto reconhecível

Abra **Settings → Projects** para dar a um projeto um nome, cor ou ícone personalizado. O OpenChamber tenta encontrar um ícone automaticamente — veja [Ícones de projeto](/pt-br/project-icons/).

> No VS Code, o OpenChamber sempre usa a pasta que você tem aberta como o único projeto, então não há nada para adicionar ou trocar. A página de configurações de Projects fica oculta lá.

## Agrupar sessões em pastas

Na visualização **Tree** da barra lateral, clique com o botão direito em uma sessão e escolha **Move to folder** para colocá-la em uma pasta, ou **New folder...** para criar uma. Uma pasta pertence à raiz do projeto ou a um worktree, e a linha da pasta tem botões para renomeá-la ou excluí-la. Excluir uma pasta mantém suas sessões; elas voltam para o projeto.

As pastas ficam salvas no servidor do OpenChamber, então tudo que está conectado ao mesmo servidor mostra as mesmas: outro computador conectado a ele, o aplicativo web e o celular. Uma mudança em um aparece nos outros em um segundo, sem recarregar. Cada servidor tem suas próprias pastas. Quais pastas estão recolhidas fica em cada dispositivo.

O celular mostra as pastas na visualização Tree, mas não pode alterá-las. Mova as sessões no desktop ou no aplicativo web.

Quando um dispositivo se conecta pela primeira vez após atualizar de uma versão que mantinha as pastas em cada dispositivo, suas pastas são adicionadas às do servidor. Uma pasta com o mesmo nome e no mesmo lugar que outra que o servidor já tem se junta a ela, e suas sessões vão junto; nada é descartado. Uma sessão que o servidor já classificou permanece na pasta do servidor.

Excluir uma sessão a tira de sua pasta, e fechar um projeto remove suas pastas. No VS Code, as pastas ficam na extensão e não são compartilhadas.

## Ambiente do projeto

Quando as ferramentas de um projeto vêm do direnv, do devenv ou de um shell Nix, os hooks do Git, o terminal e as [ações de projeto](/pt-br/project-actions/) não as encontram sozinhos. Abra **Configurações → Projetos**, escolha o projeto e, em **Ambiente**:

- adicione variáveis de que só esse projeto precisa
- ou defina um **comando de ambiente** que as imprima, por exemplo `direnv export json` ou `devenv print-dev-env --json`

O comando roda na pasta do projeto e, para um worktree, na pasta do próprio worktree. Ele roda de novo quando você faz um commit, abre um terminal ou roda uma ação, se a última execução já tiver alguns minutos, e **Rodar de novo** o executa na hora. Só ter o projeto aberto não faz ele rodar. Embaixo do campo você vê quantas variáveis a última execução adicionou, ou por que ela falhou. Uma execução que falha não adiciona nada, e o Git e o terminal continuam funcionando sem ela.

Essas variáveis vão para o Git, o terminal e as ações de projeto, somadas às de **Configurações → Geral → Variáveis de ambiente** (veja [Variáveis de ambiente](/pt-br/environment/#variáveis-para-o-opencode-o-git-e-o-terminal)). O OpenCode atende todos os projetos a partir de um único processo, então ele não recebe variáveis de projeto: coloque o que o agente precisa na lista geral.

O comando é só seu. Ele não é lido do repositório, então um repositório clonado não consegue fazer o OpenChamber rodar nada.
