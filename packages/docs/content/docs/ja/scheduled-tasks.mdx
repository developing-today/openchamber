# スケジュールタスク

スケジュールタスクは、たとえば毎日の「昨日の変更を要約」や毎週の整理のように、指定したスケジュールでプロンプトを実行します。実行時には OpenChamber が新しいセッションを開始し、自動でプロンプトを送信します。セッションサイドバー上部のボタンからスケジューラーを開きます。

## タスクを作成する

1. セッションサイドバーからスケジュールタスクダイアログを開きます。
2. タスクを追加し、名前を付けます。
3. 実行タイミングを選びます。
   - **daily** — 毎日 1 つ以上の時刻
   - **weekly** — 選んだ曜日と時刻
   - **once** — 1 回だけの日時
4. 実行内容を設定します。送信するプロンプト、使用するプロバイダー、モデル、エージェントです。プロンプトには `/review` のようなスラッシュコマンドも使えます。
5. 保存し、タスクが有効になっていることを確認します。

任意のタスクは **run now** ですぐ実行でき、期待通り動くか確認できます。

**ゴールとして実行**にチェックすると、実行は1回の返信で止まらず、プロンプトを完了まで追求します — [セッションゴール](/session-goals/)を参照してください。

## ループ：スケジュール済みタスクを Markdown ファイルとして定義する

**ループ**は、リポジトリにコミットできるポータブルな Markdown ファイルとして定義されたスケジュール済みタスクです。`.agents/loops/` にファイルを置き、スケジュール済みタスクの一覧を開くと同期されます。サーバーの再起動は不要です：

```markdown
---
name: daily-digest
schedule: "0 9 * * *"
enabled: true
model: anthropic/claude-sonnet-4-5
agent: plan
timezone: Europe/Kyiv
---
Summarize repository changes since yesterday and post the digest.
```

### ファイルの置き場所

- **プロジェクトスコープ** — プロジェクトディレクトリ、または git worktree のルートまでの任意の祖先ディレクトリにある `.agents/loops/*.md`。
- **ユーザースコープ** — `~/.agents/loops/*.md` は開くすべてのプロジェクトに適用されます。

プロジェクトループとユーザーループが同じ名前の場合、プロジェクトループが優先されます。

### フィールド

| フィールド | 意味 |
|---|---|
| `name` | タスク名（必須、最大 80 文字）。 |
| `schedule` | Cron 式（必須）— ループファイルは cron のみです。 |
| `enabled` | 実行するには `true` に設定します。ループは**デフォルトでオフ**なので、ファイルをコミットしてもタスクが勝手に実行され始めることはありません。リポジトリに付属してきたループは、あなたのマシンでスケジュール済みタスクからオンにするまで待機し、スケジュール、モデル、プロンプトが変更された後も再度待機します。`~/.agents/loops` のループは `true` だけで実行されます。 |
| `model` | `provider/model`（必須）。例：`anthropic/claude-sonnet-4-5`。 |
| `agent` | 使用するエージェント（任意）。 |
| `timezone` | IANA タイムゾーン（任意、デフォルトはサーバーのゾーン）。 |
| 本文 | 実行プロンプト（必須）。`/review src/` のようなスラッシュコマンドも可能です。 |

### ループの動作

- ファイルが存在する間、**ファイルが正**です。**編集**は組み込みのファイルエディタでそれを開き、有効化トグルはフロントマターを更新し、タスクを削除すると確認のうえ Markdown ファイルを削除します。**今すぐ実行**は引き続き利用できます。
- ランタイム状態（前回実行、次回実行、ステータス）はプロジェクト設定にあり、Markdown ファイルに書き戻されることは決してありません。
- `name` フィールドの名前変更は、タスクをその場で改名します。ループファイルが一時的に解析できなくなった場合（編集中、マージコンフリクト）、ファイルが修正されるまで、そのタスクは最後の良好な定義で保持されます。
- `daily`/`weekly`/`once` のスケジュールと目標設定は UI のみで、ループファイルは常時 cron です。

## 成功時の見え方

実行後、タスクには最後に実行された時刻、成功したかどうか、作成されたセッションへのリンクが表示されます。実行に失敗した場合は、エラーもそこに表示されます。

## 注意点

タスクは OpenChamber サーバーが実行中の間だけ発火します。閉じると、サーバーが戻るまでスケジュール実行は一時停止します。
