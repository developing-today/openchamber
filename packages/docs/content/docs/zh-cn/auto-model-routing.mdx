# 自动模型路由

在模型选择器中选 **自动**，OpenChamber 就会为你发送的每个提示挑选模型。改个错别字交给便宜又快的模型，棘手的 bug 交给你最强的模型。哪个模型负责哪类任务，你只需在设置里定一次。

## 开启

1. 确认已经设置好[分类提供方](/zh-cn/classification-providers/)。Auto 需要 Jev 来给提示分类。
2. 打开 **设置 → 路由**，勾选 **启用 Auto 模式**。
3. 选择一个 **备用模型**（以及它的思考级别）。在此之前，Auto 不会显示。
4. 看一下下面的类别，为你在意的类别指定专用模型。

一切就绪后，页面会显示 **就绪**。在任何会话中，选择模型选择器顶部的 **自动** 即可。

## 类别

每个提示都会归入一个类别。内置五个：

| 类别 | 用于 |
| --- | --- |
| Trivial | 机械性工作：重命名、错别字、格式、注释、简单命令 |
| Research | 阅读和解释代码，不做修改 |
| Implement | 明确的修改：范围清楚的功能、测试、原因已知的修复 |
| Review | 检查改动的正确性、回归、安全问题和缺失的测试；报告发现，但不做编辑 |
| Hard | 原因不明的 bug、设计与规划、安全、认证、并发、迁移、涉及金钱的逻辑 |

每个类别都可以设置：

- **模型：** 留空表示使用备用模型
- **思考：** 该模型的思考级别
- **代理：** 执行这些任务的智能体；留空则保留输入框会使用的智能体

## 面对相似提示时，Auto 会留在同一模型上

Jev 独立分类每个提示，所以两个相似的后续提示可能落入相邻的类别。为了不让会话在模型之间来回跳（每次都丢失提供商的提示缓存），Auto 会保持会话的模型，除非支持切换的证据保持一致：

- 离开会话起步时用的模型，需要连续两个提示指向同一个其他模型，或者一个 Jev 有把握的提示。
- 跳到更强的模型之后，会话会留在那里，直到连续三个提示指向别处。有把握的回答会缩短这个数量，但不会低于两个。
- Jev 无法归类的提示（置信度低、类别未知、Jev 不可达）会保持当前模型。备用模型只服务还没有历史的会话。

当 Auto 不顾 Jev 的最新回答保持了模型时，路由决定会显示 `held`。这段历史存在于服务器进程中，所以重启后会话会重新开始。会话是否处于 Auto 会被保存下来，所以重启后它仍保持 Auto，直到你选了一个真实模型。

在 **设置 → 路由** 中，关闭 **保持当前模型** 就能跟随每个提示，或者更改 **切换所需提示数** 和 **切回所需提示数**。算作“有把握”的置信度是 `routing.json` 中的 `stickiness.strongConfidence`（默认 0.9）。

## 为类别模型使用提供商池

OpenChamber 负责选择类别、思考级别和智能体。提供商的故障转移由 OpenCode 负责。在 OpenCode 的 `experimental.model_routes` 中定义有序的池，然后为类别选择路由模型。例如，把 **Trivial** 设为 `opencode-route/cheap-fast`，**Implement** 设为 `opencode-route/smart-slow`，**Hard** 和 **Review** 设为 `opencode-route/frontier-heavy`。任务决定仍由 Jev 做出；选定的路由随后会按顺序尝试它的提供商。

当出现可重试的提供商故障、额度或认证错误，以及错过首次输出期限时，OpenCode 会转移到另一个目标。已完成的请求也可以用配置的延迟或吞吐量阈值把某个目标标记为降级。冷却时间由 OpenCode 进程中的会话共享，并在重启后恢复；OpenCode 会把每个路由决定、每次尝试（确切的错误代码和消息、耗时、token 数量）和冷却都记录到它的数据库中，供以后分析。一旦任何回答或工具输出已经开始，这一轮就永远不会重放。

OpenCode 还会读取每个响应的限流标头，在提供商开始拒绝之前，就把流量从那个提供商声称周期已用完的目标上移走。

池还可以在转移之前向一个目标发出多次请求（`attempts`，默认总共两次），在第一个目标沉默时启动下一个目标（`hedgeAfterMs`），给某个目标的请求和 token 设上限（`budgets`，它会统计 OpenCode 向该目标发出的每个请求，包括标题之类的后台请求），并由智能体根据它记录的历史来调优。这些是 OpenCode 的路由选项；请参阅它的配置参考。

时间表在指定的日期或时段更改目标的权重，例如在某个提供商的高峰时段少给它发请求。单个池的时间表在 **设置 → 路由 → 模型池** 中该池的高级选项里；池列表下方的 **跨池时间表** 会在所有池中，或仅在你列出的池中，更改匹配的目标。每个时间表可以设置星期、每月日期、开始和结束时间、时区，以及一个乘到权重上的系数或一个替换权重的值，二者选一。时段之外，使用配置的权重。OpenCode 还会应用其他配置文件中的时间表，例如项目的 `opencode.json`。设置中以只读方式列出这些时间表，并标明要去哪个文件编辑。

每个池还可以说明它是做什么用的。在 **设置 → 路由 → 模型池** 中，打开一个池，填写 **描述**，一行如“跨许多文件的长重构；慢；花费最多”，以及 **详情**，一段说明什么时候该用这个池、什么时候不该用的文字。当某个类别的模型是一个池时，Jev 会把这两项连同该类别的描述一起阅读。OpenChamber 会把它们作为 `description` 和 `details` 保存到 `opencode.json` 的路由上。OpenCode 会忽略这两个键，所以按 OpenCode 的 JSON 架构检查该文件的编辑器可能会标记它们。

Jev 通过阅读类别的名称和描述来给提示分类，所以描述起的是指令的作用。写清楚哪些属于这个类别、哪些不属于。你可以编辑、关闭、删除或新增类别，改主意时还可以恢复内置类别。Auto 至少需要两个已开启的类别。

### 查看哪些会话共用一个目标

某个目标的套餐用完时，该目标上的所有会话会同时切换到下一个目标，每个会话都要从空的提示缓存重新开始。**设置 → 路由 → 模型池 → 池健康状况** 会显示每个池中每个目标在最近 15 分钟内被多少个会话使用，并在两个或更多会话共用一个目标时发出警告。

在那里把目标关联到你的某个套餐，就能看到预测：该目标的近期用量，加上关联到同一套餐的所有其他目标的用量，按套餐的额度周期折算。按请求、消息或 token 计数的周期会有预测，按美元或百分比计数的周期没有。这个数字是根据最近 24 小时 OpenCode 流量得出的估算，看不到 OpenCode 之外的用量。在加权或轮询的池中，用量达到周期 70% 及以上的目标会出现 **降低权重** 按钮，它会把该目标的权重减半，让新会话更多地流向其他目标。

## 发送时会发生什么

1. OpenChamber 把你的消息和最近几轮的简短摘录发给 Jev。
2. Jev 选出一个类别，并给出它有多确定。
3. 会话切换到该类别的模型、思考级别和智能体，然后发出你的消息。

每条消息都会重新分类，所以一个会话可以在简单提问时用便宜的模型，下一个请求时换成你最强的模型。输入框会一直显示 **自动**，智能体和思考级别的选择会被隐藏，因为它们由类别决定。

以下情况由备用模型回答：

- Jev 不够确定（低于 60%）
- Jev 出错或超过四秒没有回应
- 该类别没有自己的模型

在选择器里选择任何具体模型，会话就会退出 Auto。要回来，再选一次 **自动**。你也可以在 **设置 → 会话** 中把 Auto 设为新会话的默认模型。

## 套餐、用量与回顾

**设置 → 路由 → 套餐与用量** 保存回顾无法衡量的东西：你的订阅及其额度周期（名称、单位、上限、周期有多长、如何重置）、费用和到期日期、每个套餐上次检查的日期和检查来源、每个模型的成本等级（`plan`、`common`、`medium`、`high`，以及涵盖它的套餐）、每个池是做什么用的，以及关于使用感受的备注。备注会按你写下的样子保存，永不重写。用它们记录像“Claude 用完得太快”或者“到月底我总是剩着 GPT”这样的事情；回顾会把它们与使用历史对照衡量。

两个按钮会开启一个新聊天，并备好一条可以发送的命令：

- **复核路由** 会运行 `/routing-review`。它会阅读路由历史（请求、token、成本、会话，以及哪些池使用或跳过了每个提供商和模型）、套餐记录与备注，并提出修改建议。在你批准某项具体修改之前，它不会改变任何东西。
- **更新套餐** 会运行 `/plan-update`。它会找出缺少细节或上次检查在一个多月前的套餐，询问它需要的少数几个字段，并记录你的回答。

这些记录以 `plans.json` 和 `plan-notes.jsonl` 的形式存放在 OpenCode 的数据目录中，其中的任何内容都不会过期。历史也会保留；`route_usage` 可以读取它的任意时段。

## 在哪里可用

Auto 运行在 OpenChamber 服务器上：桌面应用、网页应用，以及连接到它们的手机。VS Code 不提供 Auto，因为扩展直接和 OpenCode 通信。
