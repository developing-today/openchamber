# 예약 작업

예약 작업은 일정에 따라 프롬프트를 대신 실행합니다. 예를 들어 매일 "어제 변경 사항 요약"이나 주간 정리 같은 것입니다. 실행되면 OpenChamber가 새 세션을 시작하고 프롬프트를 알아서 보냅니다. 세션 사이드바 상단의 버튼에서 스케줄러를 엽니다.

## 작업 만들기

1. 세션 사이드바에서 예약 작업 대화 상자를 엽니다.
2. 작업을 추가하고 이름을 지정합니다.
3. 실행 시점을 선택합니다.
   - **daily** — 매일 하나 이상의 시각에
   - **weekly** — 선택한 요일과 시각에
   - **once** — 단일 날짜와 시각에
4. 동작을 설정합니다. 보낼 프롬프트와 사용할 공급자, 모델, 에이전트를 지정합니다. 프롬프트는 `/review`처럼 슬래시 명령일 수 있습니다.
5. 저장하고 작업이 활성화되어 있는지 확인합니다.

**run now**로 작업을 즉시 실행하여 기대대로 동작하는지 확인할 수 있습니다.

**목표로 실행**을 체크하면 실행이 한 번의 답변에서 멈추지 않고 프롬프트를 완료까지 추진합니다 — [세션 목표](/session-goals/)를 참고하세요.

## 루프: 마크다운 파일로 정의하는 예약 작업

**루프**는 저장소에 커밋할 수 있는 이식 가능한 마크다운 파일로 정의된 예약 작업입니다. `.agents/loops/`에 파일을 넣고 예약 작업 목록을 열면 동기화됩니다. 서버를 재시작할 필요가 없습니다:

```markdown
---
name: daily-digest
schedule: "0 9 * * *"
enabled: true
model: anthropic/claude-sonnet-4-5
agent: plan
timezone: Europe/Kyiv
---
Summarize repository changes since yesterday and post the digest.
```

### 파일 위치

- **프로젝트 범위** — 프로젝트 디렉터리 또는 git 워크트리 루트까지의 모든 상위 디렉터리에 있는 `.agents/loops/*.md`.
- **사용자 범위** — `~/.agents/loops/*.md`는 여는 모든 프로젝트에 적용됩니다.

프로젝트 루프와 사용자 루프가 같은 이름을 가지면, 프로젝트 루프가 우선합니다.

### 필드

| 필드 | 의미 |
|---|---|
| `name` | 작업 이름(필수, 최대 80자). |
| `schedule` | Cron 표현식(필수) — 루프 파일은 cron 전용입니다. |
| `enabled` | 실행하려면 `true`로 설정하세요. 루프는 **기본적으로 꺼져 있어**, 파일을 커밋해도 작업이 저절로 실행되기 시작하지 않습니다. 저장소와 함께 온 루프는 내 컴퓨터의 예약 작업에서 켤 때까지 기다리고, 일정·모델·프롬프트가 변경된 뒤에도 다시 기다립니다. `~/.agents/loops`의 루프는 `true`만으로 실행됩니다. |
| `model` | `provider/model`(필수), 예: `anthropic/claude-sonnet-4-5`. |
| `agent` | 사용할 에이전트(선택). |
| `timezone` | IANA 시간대(선택, 기본값은 서버 시간대). |
| 본문 | 실행 프롬프트(필수). `/review src/` 같은 슬래시 명령일 수 있습니다. |

### 루프의 동작 방식

- 파일이 존재하는 동안 **파일이 기준**입니다. **편집**은 내장 파일 편집기에서 파일을 열고, 활성화 토글은 프론트매터를 업데이트하며, 작업을 삭제하면 확인 후 마크다운 파일을 삭제합니다. **지금 실행**은 계속 사용할 수 있습니다.
- 런타임 상태(마지막 실행, 다음 실행, 상태)는 프로젝트 설정에 있으며 마크다운 파일에 다시 기록되지 않습니다.
- `name` 필드의 이름을 바꾸면 작업이 제자리에서 이름이 바뀝니다. 루프 파일이 일시적으로 파싱에 실패하면(편집 중, 병합 충돌), 파일이 수정될 때까지 그 작업은 마지막 정상 정의로 유지됩니다.
- `daily`/`weekly`/`once` 일정과 목표 설정은 UI 전용으로 남으며, 루프 파일은 항상 cron입니다.

## 성공이란 어떤 모습인가

실행 후 작업에는 마지막 실행 시각, 성공 여부, 생성된 세션으로의 링크가 표시됩니다. 실행이 실패하면 오류도 거기에 표시됩니다.

## 유의할 점

작업은 OpenChamber 서버가 실행 중일 때만 동작합니다. 서버를 닫으면 다시 켤 때까지 예약 실행이 일시 중지됩니다.
