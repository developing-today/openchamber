# Заплановані завдання

Заплановане завдання запускає промпт за вас за розкладом — наприклад, щоденне «підсумуй вчорашні зміни» чи щотижневе прибирання. Коли воно спрацьовує, OpenChamber починає нову сесію й надсилає промпт самостійно. Відкрийте планувальник із кнопки вгорі бічної панелі сесій.

## Створення завдання

1. Відкрийте діалог запланованих завдань із бічної панелі сесій.
2. Додайте завдання й дайте йому назву.
3. Виберіть, коли воно запускається:
   - **daily** — в один або кілька моментів щодня
   - **weekly** — у вибрані дні тижня та час
   - **once** — одна дата й час
4. Задайте, що воно робить: промпт для надсилання, а також провайдера, модель і агента для використання. Промпт може бути слеш-командою, як-от `/review`.
5. Збережіть і переконайтеся, що завдання ввімкнене.

Ви можете запустити будь-яке завдання негайно через **run now**, щоб перевірити, що воно робить те, що ви очікуєте.

Позначте **Run as goal**, щоб запуск доводив промпт до завершення, а не зупинявся після однієї відповіді — див. [Цілі сесії](/session-goals/).

## Цикли: заплановані завдання як файли markdown

**Цикл** — це заплановане завдання, визначене як портативний файл markdown, який ви можете закомітити у свій репозиторій. Покладіть файл у `.agents/loops/` і відкрийте список запланованих завдань, щоб синхронізувати його — перезапуск сервера не потрібен:

```markdown
---
name: daily-digest
schedule: "0 9 * * *"
enabled: true
model: anthropic/claude-sonnet-4-5
agent: plan
timezone: Europe/Kyiv
---
Summarize repository changes since yesterday and post the digest.
```

### Де живуть файли

- **Область проєкту** — `.agents/loops/*.md` у теці проєкту або будь-якій батьківській теці аж до кореня worktree git.
- **Область користувача** — `~/.agents/loops/*.md` застосовується до кожного проєкту, який ви відкриваєте.

Якщо цикл проєкту й цикл користувача мають ту саму назву, перемагає цикл проєкту.

### Поля

| Поле | Значення |
|---|---|
| `name` | Назва завдання (обов'язково, макс. 80 символів). |
| `schedule` | Вираз cron (обов'язково) — файли циклів лише cron. |
| `enabled` | Встановіть `true`, щоб запускати. Цикли **вимкнено за замовчуванням**, тож комічення файлу ніколи не починає виконувати завдання само по собі. Цикл, що прийшов із репозиторієм, також чекає, доки ви ввімкнете його в Запланованих завданнях на своїй машині, і знову — після зміни його розкладу, моделі чи промпту. Цикли в `~/.agents/loops` працюють лише на `true`. |
| `model` | `provider/model` (обов'язково), напр. `anthropic/claude-sonnet-4-5`. |
| `agent` | Агент для використання (необов'язково). |
| `timezone` | Часовий пояс IANA (необов'язково, за замовчуванням зона сервера). |
| тіло | Промпт виконання (обов'язково). Може бути слеш-командою, як `/review src/`. |

### Як поводяться цикли

- **Файл є авторитетним**, доки існує. **Редагувати** відкриває його у вбудованому редакторі файлів, перемикач увімкнення оновлює його фронтматер, а видалення завдання видаляє файл markdown після підтвердження. **Запустити зараз** лишається доступним.
- Стан виконання (останній запуск, наступний запуск, статус) живе в конфігурації проєкту й ніколи не записується назад у файл markdown.
- Перейменування поля `name` перейменовує завдання на місці. Якщо файл циклу тимчасово не вдається розібрати (посеред редагування, конфлікт злиття), його завдання зберігається з останнім справним визначенням, доки файл не виправлять.
- Розклади `daily`/`weekly`/`once` і налаштування цілей лишаються лише в UI; файли циклів — завжди cron.

## Як виглядає успіх

Після запуску завдання показує, коли воно востаннє виконувалося, чи воно успішне, і посилання на сесію, яку воно створило. Якщо запуск збоїть, помилка теж показується там.

## Майте на увазі

Завдання спрацьовують лише поки запущений сервер OpenChamber. Якщо ви його закриєте, заплановані запуски призупиняються, доки він не повернеться.
